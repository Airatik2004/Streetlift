# Воркаут — офлайн-трекер силовых тренировок

Android-приложение (Kotlin, Jetpack Compose, Material 3, тёмная тема, акцент `#2196F3`) для воркаута и стритлифтинга:
4-дневный цикл без привязки к дням недели, знаковый дополнительный вес, RIR в каждом подходе,
движок двойной прогрессии с авторегуляцией и гибридной разгрузкой, встроенный таймер отдыха с рекомендациями.

## Сборка APK через GitHub

1. Создайте репозиторий (можно приватный) и запушьте в него содержимое этой папки.
2. Откройте вкладку **Actions** → workflow **Build APK** запустится сам при пуше (или вручную: *Run workflow*).
3. Через ~5–8 минут внизу страницы запуска появятся артефакты:
   - `streetlift-debug-apk` — debug-сборка (`ru.streetlift.tracker.debug`, ставится рядом с release);
   - `streetlift-release-apk` — release-сборка (`ru.streetlift.tracker`, R8-минификация);
   - `unit-test-report` — отчёт тестов движка.

### Подпись release (важно для обновлений)

Без секретов release подписывается **debug-ключом раннера, который каждый раз новый** — поверх такой сборки
обновиться нельзя, придётся удалять приложение (данные перед этим сохраните через «История → Экспорт»).
Чтобы обновления ставились поверх, создайте свой ключ один раз:

```bash
keytool -genkeypair -v -keystore streetlift.jks -alias streetlift -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 streetlift.jks > streetlift.jks.b64     # на Windows: certutil -encode streetlift.jks streetlift.b64
```

И добавьте в *Settings → Secrets and variables → Actions*:

| Секрет | Значение |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | содержимое `streetlift.jks.b64` |
| `SIGNING_STORE_PASSWORD` | пароль хранилища |
| `SIGNING_KEY_ALIAS` | `streetlift` |
| `SIGNING_KEY_PASSWORD` | пароль ключа |

Сам `.jks` в репозиторий не кладите (он в `.gitignore`).

## Правила движка (как реализовано)

- **Новый вес** → `minSets` подходов, цель `minReps`.
- **1-й круг на весе** — `minSets`; со 2-го — `maxSets`, если средний RIR ≥ нижней границы целевого RIR.
- **Повышение веса**: все запланированные подходы выполнены, в каждом `reps ≥ maxReps` и `RIR ≥ targetRirMin`
  → `вес += шаг`, подходы сбрасываются до `minSets`.
- **Утомление**: повторы < `minReps` в любом подходе или RIR 0 в ≥ 2 подходах → вес не растёт, подходов −1
  (не ниже `minSets − 1`). Следующий нормальный круг сначала возвращает `minSets`.
- **Цель повторов** на следующий круг = минимум достигнутых + 1 (в пределах диапазона).
- **Плановая разгрузка**: каждый N-й круг (по умолчанию 5-й) — вес 100%, подходы ×0.5 с округлением вверх
  (5→3, 4→2, минимум 2), RIR 3–4, отдых −30 с. После разгрузочного круга счётчик = 1.
  Отмена плановой разгрузки кнопкой на главной тоже начинает новый мезоцикл.
- **Аварийная разгрузка**: оценка тренировки = среднее (повторы + RIR) на подход; если она падает
  2 круга подряд на одном и том же весе — следующий круг этого упражнения проходит в режиме разгрузки.
- **Ручной вес** в редакторе обнуляет историю сравнения для аварийной разгрузки.

## Стадии рычага и калибровка

- У упражнения есть опциональная `leverageStage`. Справочник: Закрытый → Полузакрытый → Полуоткрытый → Открытый →
  Ноги врозь (широкие, >60°) → Ноги врозь (узкие, ~30°) → Фулл, плюс свои варианты (добавляются в конец).
  В шаблоне горизонт (день 2) и передний вис (день 4) стоят на «Полуоткрытом».
- Внутри стадии работает обычная двойная прогрессия по знаковому весу. Сложность между стадиями не вычисляется.
- **Смена стадии** (в редакторе): снимок плана старой стадии уходит в «Архив стадий» (вкладка История),
  сравнение показателей обнуляется, упражнение на 1 круг переходит в `CALIBRATION`. Каждый подход хранит свою стадию,
  поэтому в истории разные стадии идут разными строками.
- **Первый запуск**: экран «Настройка стартовых параметров» — стадия, известный рабочий вес или переключатель
  «Подобрать на тренировке (Калибровка)». Повторно открывается из редактора цикла.
- **`CALIBRATION`**: 3 подхода, коридор повторений упражнения, RIR 2, подсказка на экране тренировки. Вес и стадию можно
  менять перед каждым подходом. По завершении вес, повторы и стадия **последнего** подхода становятся стартом
  (`minSets` × эти повторы), статус → `ACTIVE`. Калибровка важнее плановой разгрузки. Если калибровку пропустить,
  упражнение останется в ней до следующего раза.
- Схема БД — версия 2 (`fallbackToDestructiveMigration`: если ставили прошлую сборку, база пересоздастся).
